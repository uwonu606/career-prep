# 에이전트 프롬프트 템플릿

`SKILL.md`의 메인이 `<…>` 자리표시를 채워 **그대로 Agent 프롬프트로** 쓴다. 템플릿은 셋 — 지도(1단계), 묶음(2단계, 묶음당 하나), 수정(2단계, 파서가 깨졌을 때).

**수집 규칙은 [`catalog.md`](catalog.md)가 정한다** — #0이 접근 등급·호스트당 간격·재시도·깊이 한도를, #8이 금지 목록을 갖는다. 접근 등급만 각 템플릿의 "하지 말 것"에 한 번 더 적는다 — 요청이 이미 나간 뒤에는 되돌릴 수 없어서다(에이피알 조사에서 robots 판정 전에 1회 받은 실수 ①).

저장소 쪽은 세 템플릿이 같다: git 명령을 쓰지 않고, `career-prep/`를 건드리지 않고, 각 템플릿 "해야 할 일"에 적힌 파일만 만든다.

## 1. 지도 에이전트

### 역할
회사 한 곳의 **자료 지도**를 만든다. `catalog.md`의 18각도마다 자료가 있는지·없는지·사람이 봐야 하는지·절차가 깨졌는지를 표의 "있는지 확인하는 절차" 열대로 밟아 판정하고, 19번째로 이 회사에만 있는 자료를 한 번 찾는다. 자료를 읽거나 해석하지 않는다 — **있는지만 본다.**

### 넘겨줄 것
- `<법인명>` — 확정된 법인명. 모든 검색어와 필터의 기준. `<브랜드명>` `<영문명>`(GitHub 검색용) `<corp_code>` `<stock_code>` `<홈페이지 URL>` `<대표명>`(각도 11 검색어) — 모르면 `~`.
- `<키 유무>` — `DART_API_KEY` 있음/없음(메인이 `.env` 파일의 존재만 보고 판단한다 — 내용은 읽지 않는다). 있으면 D2(`dart_fetch.py --check`, 스크립트가 키를 스스로 읽음), 없으면 D1만. `<SKILL>` — SKILL.md가 있는 디렉토리 절대 경로(D2에 필요).
- `<조사일>` YYYY-MM-DD · `<CATALOG>` catalog.md 절대 경로 · `<WORK>` 임시물(홈페이지 HTML·응답 본문)을 둘 작업 디렉토리 절대 경로. **메인이 `mkdir -p`로 미리 만들어 넘긴다**(SKILL.md 1단계).

### 해야 할 일
1. `<CATALOG>`를 전부 읽는다 — #0 읽는 법, #8 금지 목록, #9 반환 형식까지.
2. #2~#6 표의 "있는지 확인하는 절차" 열을 각도 순으로 **그대로** 실행한다. 명령은 표 아래 블록(D1·D2·R0·H1·H2·R1·G1·G2)을 쓰고, `UA`는 블록의 식별 문자열 그대로, 임시 파일은 `<WORK>`에 둔다. 의존(4→5·7·13, R0→R1)만 지키면 독립 각도의 WebSearch는 병렬로 돌려도 된다 — 시운전은 5라운드 병렬로 8분이었다 ①.
3. 각도 1~3: `<키 유무>`가 있음이면 D2(`python3 <SKILL>/scripts/dart_fetch.py "<법인명>" --check`)로 — 종료 0이면 `있음`(stdout의 `latest_A001`·`report_nm`을 링크 열에), 종료 2에 `F001>0`이면 `없음`("감사보고서만"), 둘 다 0이면 `없음`, 종료 4면 `실패`(후보를 사유에), 5·6·7이면 `실패`(stderr 원문). 없음이면 D1(A001·F001)로 유무만 본다. D1에서 A001>0이면 `실패`(사유 "키 없음 — 사업보고서 N건 있음"), A001=0·F001>0이면 `없음`(사유 "감사보고서만"), 둘 다 0이면 `없음`. 각도 2·3은 1을 따른다 — 1이 `없음`이면 `없음`("사업보고서 없음"), `실패(키 없음)`이면 같은 `실패`. `<corp_code>`가 `~`이고 해외 법인이면 1~3은 `없음`("한국 법인 아님, DART 해당 없음").
4. 각도 4의 홈페이지 HTML은 **1회만** 받아 `<WORK>/homepage.html`로 두고, 5·7·13은 이 파일에서 grep한다. 4의 링크 열에 `(HTML: <WORK>/homepage.html)`을 덧붙인다 — 묶음 ②가 두 번 받지 않도록.
5. 등급 B 절차는 WebSearch(필요하면 그 결과 링크 WebFetch 1건), 등급 C는 WebSearch 스니펫과 링크만. 검색 결과의 법인명이 `<법인명>`과 다르면 버린다(그룹사 이름 겹침).
6. 19번째: #7 표를 출발점으로 업종·회사 특유의 자료를 **한 번** 찾는다. 새 소스는 `robots.txt`와 이용약관을 **둘 다** 읽어 등급을 붙인다. 카탈로그 파일은 고치지 않고 19행의 링크 열에 `제안: <자료 유형> · <어디에> · <확인 절차 한 문장> · 등급 <A/B/C>(근거)`를 적는다 — 추가는 메인이 한다.

### 하지 말 것
자료 내용을 읽고 요약·해석하기 · 접근 등급 넘기기(#0) · 홈페이지 두 번 받기 · 브라우저 UA로 위장하기 · 카탈로그와 그 밖의 파일 수정 · 상태 어휘 밖의 말 쓰기 · `없음`과 `실패` 섞기(절차를 끝까지 밟았는데 없으면 `없음`, 절차가 깨졌으면 `실패`) · 서브도메인 프로빙·컨퍼런스 URL 프로빙(카탈로그가 쓰지 않는다고 적은 것).

### 반환 형식
[`catalog.md`](catalog.md) #9 그대로 — 18행 + 19행, 번호순, 앞뒤에 다른 문장 없이. 상태 어휘와 링크·사유 열의 내용은 #9가 정한다. 유일한 예외: 법인 변동 신호(분할·합병·사명 변경 결의)를 봤으면 표 아래 `주의:` 한 줄.

## 2. 묶음 에이전트

### 역할
묶음 `<묶음>` 하나의 `있음`·`수동` 행만 받아 자료를 읽고 **사실만** 돌려준다. 해석·판정·교차점은 메인의 일이다. 반환문은 메인이 **편집 없이** `artifacts/findings/findings-<묶음>.md`로 저장하므로 `catalog.md` #10 형식을 그대로 지킨다.

### 넘겨줄 것
- `<묶음>` — `dart`·`company`·`external`·`market`·`reputation` 중 하나(카탈로그 ①~⑤ 순).
- `<지도 행>` — 이 묶음의 `있음`·`수동` 행만, #9 형식 그대로. `<법인명>` `<브랜드명>` `<영문명>` `<대표명>` `<조사일>`.
- `<ARTIFACTS>` — `career/companies/<slug>/artifacts` 절대 경로 · `<CATALOG>` — catalog.md 절대 경로.
- 묶음 `company`에만: `<job_url>`(사용자가 준 공고 URL, 없으면 `~`) · `<HOMEPAGE_HTML>`(지도 에이전트가 받아 둔 파일 경로, 다시 받지 않는다).
- 묶음 `dart`에만: `<corp_code>` · `<SKILL>`(SKILL.md가 있는 디렉토리 절대 경로) · `<FIXTURES>`(픽스처 디렉토리 절대 경로 = `$ADD_COMPANY_FIXTURES`, 필수 — 없으면 메인이 사용자에게 묻는다) · `<키 유무>`.

### 해야 할 일
1. `<CATALOG>`의 #0·#8·#10과 자기 묶음의 절(#2~#6 중 하나)을 읽는다.
2. `<지도 행>`의 링크를 그 행의 등급대로 읽는다(#0). 등급 C(`수동` 행)는 WebSearch 스니펫에서 읽히는 사실만 적고, 나머지는 "못 찾은 것"에 URL과 "사람이 봐야 함"으로 보낸다.
3. 깊이·숫자 표기·법인명 필터는 #0과 #10이 정한다 — 읽기 전에 둘 다 연다.
4. 묶음 `company`: `<job_url>`이 `~`가 아니면 WebFetch 1건으로 읽고 각도 5의 항목으로 적는다. `<HOMEPAGE_HTML>`이 있으면 각도 4는 그 파일을 읽는다.

### DART 묶음 전용 절 (`<묶음>` = `dart`)
스크립트 세 개를 이 순서로, 각각 한 번만 돌린다. 산출은 전부 `<ARTIFACTS>/dart/`. 파일명은 1번이 쓴 `manifest.json`에서 읽는다 — 본문 XML은 `files.document`(= `{rcept_no}.xml`), 직원 현황은 `files.emp`(연도→파일명), 임원 현황은 `files.exec`(없으면 `null`).

```
python3 <SKILL>/scripts/dart_fetch.py <corp_code> --out <ARTIFACTS>/dart --years 5
python3 <SKILL>/scripts/dart_extract.py <ARTIFACTS>/dart/<rcept_no>.xml --out <ARTIFACTS>/dart/business.md --people <ARTIFACTS>/dart/people-report.md
python3 <SKILL>/scripts/dart_tables.py --emp <ARTIFACTS>/dart/empSttus-<YYYY>.json ... --exec <ARTIFACTS>/dart/exctvSttus-<YYYY>.json --out <ARTIFACTS>/dart/people-tables.md
```

종료 코드별 행동(스크립트마다 뜻이 다르다 — `--help` 기준):
- `dart_fetch.py` — **0** 다음으로. **2** 사업보고서 없음(감사보고서만 내는 회사, `company.json`은 저장됨) → 각도 1~3을 "못 찾은 것"에 `없음`으로, 이유는 stderr 그대로. **4** 법인명 확정 실패 → stderr의 후보 표를 그대로 "못 찾은 것"에 옮기고 끝낸다(고르지 않는다). **5** 키 없음 → "못 찾은 것"에 `실패(키 없음)`과 stderr의 발급 URL. **6** API 오류(상태코드·메시지) · **7** 네트워크 오류 → `실패`, stderr 원문. `<corp_code>`가 `~`이면 `<법인명>`을 넘긴다.
- `dart_extract.py` — **0** 다음으로(stderr에 "연구개발 절 없음"이 있으면 금융업 서식이다 — 실패가 아니고 사실이니 "발견"에 `[각도 1] 「II. 사업의 내용」에 연구개발 절 없음(금융업 서식)`으로 적는다). **2** 절을 못 찾음 · **3** XML 파싱 실패 → 아래 픽스처 절차. **1** 읽기·쓰기 실패 → `실패`, stderr 원문.
- `dart_tables.py` — **0** 다음으로. **2** 표로 만들 데이터 없음 → 해당 각도(2 또는 3)를 "못 찾은 것"에 `없음`, stderr 이유. **3** JSON 읽기 실패 → `실패`, stderr 원문. `files.exec`가 `null`이면 `--exec`를 빼고 돈다.

**픽스처 절차**(extract 종료 2·3): ① `<ARTIFACTS>/dart/<rcept_no>.xml`을 `<FIXTURES>/<rcept_no>.xml`로 **원문 그대로** 복사한다(고치지 않는다). ② `<FIXTURES>/README.md` 표에 한 줄 붙인다 — 열은 `파일 | 회사 | 결산 | 스키마 | 목차 세대 | 비고`; 회사·결산은 `manifest.json`의 `corp_name`·`report_nm`, 스키마는 XML 머리의 `dart3.xsd`/`dart4.xsd`, 목차 세대는 `rcept_dt`가 2021-08 이전이면 "2021.7 이전" 아니면 "2021.7 이후", 비고에 종료 코드와 stderr 한 줄. ③ `<FIXTURES>/expect.json`에 `"<rcept_no>.xml": {"ii_subsections": null, "viii_subsections": null, "has_rnd": null}`을 추가한다 — 값을 확실히 알면 적고, 모르면 `null`로 둔다(수정 에이전트가 채운다). ④ "못 찾은 것"에 `[각도 1] 파서 실패(종료 N) — <stderr 한 줄>. 픽스처 <FIXTURES>/<rcept_no>.xml 추가함`으로 보고하고 3번 스크립트는 그대로 진행한다. 파서를 손으로 우회하지 않는다 — 정규식으로 본문을 자르거나 XML을 고쳐 다시 넣지 않는다.

성공하면 `business.md`·`people-report.md`·`people-tables.md`를 읽고 사실을 뽑는다. 출처는 `artifacts/dart/business.md#<절 제목 앵커>`(예 `#4-매출-및-수주상황`), `artifacts/dart/people-tables.md#직원-현황`·`#임원-현황` 꼴로 단다. 앵커는 **business.md의 실제 `##` 제목**에서 만든다(소문자, 괄호·점 제거, 공백→하이픈) — 업종 접두어가 붙거나(`## 6. (제조서비스업)주요계약 및 연구개발활동` → `#6-제조서비스업주요계약-및-연구개발활동`) 같은 번호가 `(금융업)`으로 한 번 더 나올 수 있다(카카오 ①). 예시 앵커를 그대로 베끼지 않는다.

### 하지 말 것
해석·판정·교차점 쓰기 · 지도 행에 없는 각도 파기 · 접근 등급 넘기기(#0) · 계산해 새 숫자 만들기(각도 5의 셈만 예외) · 스크립트 재실행·재시도 · 파서 우회 · `<ARTIFACTS>/dart/`와 픽스처 셋 밖의 파일 만들기(findings 저장은 메인이 한다) · 다른 묶음의 자료 인용.

### 반환 형식
[`catalog.md`](catalog.md) #10 그대로 — 머리 한 줄 + `## 발견` + `## 못 찾은 것`이고, 한 항목은 사실 한 문장 + 출처 하나 + 각도 번호다. 메인이 편집 없이 저장하므로 두 절 사이·앞뒤에 다른 문장을 넣지 않는다.

## 3. 수정 에이전트

### 역할
`dart_extract.py`가 새 원문에서 깨졌다. 원인을 진단해 **파서를 고치고**, 새 픽스처를 포함한 전 픽스처를 통과시키고, 무엇을 왜 어떻게 바꿨는지 사람이 검토할 수 있게 요약한다.

### 넘겨줄 것
- `<FIXTURE_XML>` — 실패한 픽스처 절대 경로(`<FIXTURES>/<rcept_no>.xml`) · `<STDERR>` — 실패 실행의 종료 코드와 stderr 원문 · `<rcept_no>`.
- `<EXTRACT>` — `<SKILL>/scripts/dart_extract.py` 절대 경로 · `<TEST_CMD>` — `python3 <SKILL>/scripts/test_extract.py <FIXTURES>` · `<EXPECT>` — `<FIXTURES>/expect.json` 절대 경로.

### 해야 할 일
1. 먼저 `<TEST_CMD>`를 돌려 현재 실패를 기록한다. `<EXPECT>`의 `null` 기대값은 `assertEqual(…, None)`이라 채우기 전까지 붉다 — 그건 4에서 채운다.
2. 진단한다. 종료 3이면 전처리(`&cr;`·`&nbsp;`·미정의 엔티티·한글 의사 태그 치환)가 놓친 패턴을 원문에서 찾는다. 종료 2면 `SECTION-1`의 직속 `TITLE` 정규화·정규식(`BUSINESS_TITLE`·`PEOPLE_TITLE`·`PEOPLE_SUB_TITLE`)이 이 원문의 표기를 못 맞춘 것인지, 골격(dart4 등)이 달라 후손 탐색이 닿지 않는지 본다. 원문의 해당 부분을 인용해 원인을 한 문장으로 적는다.
3. `<EXTRACT>`를 고친다. 절 식별은 `SECTION-1` 단위 + `TITLE` 정규화, 파싱은 전처리 뒤 strict — 이 두 원칙은 유지한다. 실패는 여전히 비0 종료 + stderr 사유여야 한다.
4. `<EXPECT>`의 `null`을 채운다. 값은 파서 출력이 아니라 **원문에서 독립적으로 센 값**이다(예: II `SECTION-1` 아래 `SECTION-2`의 `TITLE`을 grep으로 셈, 연구개발 여부는 그 제목에서). 세는 명령과 결과를 요약에 적는다. 사람은 DART 뷰어 `https://dart.fss.or.kr/dsaf001/main.do?rcptNo=<rcept_no>`를 브라우저로 열어 대조한다 — 에이전트는 이 주소를 fetch하지 않는다.
5. `<TEST_CMD>`가 전부 통과할 때까지 2~4를 반복하고, 픽스처 각각에 `python3 <EXTRACT> <xml> --out /dev/null --people /dev/null`을 돌려 종료 0을 확인한다.

### 하지 말 것
기존 픽스처의 기대값 바꾸기(바꿔야만 하면 어느 값을 왜 바꾸는지 요약에 명시) · recover 모드(관대한 파싱) 도입 · 표준 라이브러리 밖 패키지 · 정규식 텍스트 컷으로 절 자르기 · 픽스처 XML 수정 · `test_extract.py`의 검사 약화나 삭제 · git 명령 · `<EXTRACT>`·`<EXPECT>` 밖의 파일 수정.

    ## 무엇이 깨졌나 — 원인 한 문장 + 원문 인용(줄 번호)
    ## 어떻게 고쳤나 — 함수/줄 단위로 변경 전 → 후
    ## 기대값 — expect.json 항목과 그 값을 센 명령·결과
    ## 테스트 출력 — <TEST_CMD> 출력 원문과 종료 코드, 픽스처별 CLI 종료 코드
    ## 남은 위험 — 있으면(없으면 "없음")

메인은 "테스트 출력"이 전부 OK일 때만 DART 묶음 에이전트를 재실행한다. 아니면 그 각도는 `수동` + DART 뷰어 링크로 남긴다.
