# 저장 형식

## 레이아웃

```
career/
├── index.md                     자동 생성. scripts/build_index.py 가 만든다
├── backlog.md                   다음에 캘 장면 후보
├── self.md                      역량 주장
├── projects/<slug>/
│   ├── project.md
│   └── artifacts/               회고·다이어그램·데모 링크·JD 스크랩
├── episodes/<slug>.md
└── applications/                (아직 안 씀)
```

`career/`는 **사용자의 현재 작업 디렉토리 바로 아래**에 둔다.

파일명은 영문 kebab slug이고 그것이 곧 참조 id다. 한글 제목은 frontmatter `title`에 둔다.

**에피소드는 평평하게 둔다.** 프로젝트 디렉토리 안에 넣지 않는다 — 프로젝트에 속하지 않는 경험(알바·동아리·개인공부)과 여러 프로젝트에 걸친 사건이 갈 곳을 잃는다. 소속은 `projects:` 참조가 담당한다.

## 에피소드

```markdown
---
id: concurrent-payment-lock
title: 동시 결제로 재고가 음수가 된 버그
projects: [secondhand-market]      # 0개(프로젝트 밖) · 1개 · 2개 이상(걸친 사건) 모두 정상
related: []                        # 이어지는 다른 에피소드 id
date: 2025-04
skills: [동시성, 디버깅]            # references/vocabulary.md 의 어휘
evidence: verified                 # verified | recalled | unacquired
evidence_links:
  - https://github.com/.../pull/42
open_questions:
  - 결과 — 3회 시도(고친 순간의 화면 / 남은 숫자 / 이전 상태 대조) 전부 미도달.
    같은 각도로 다시 묻지 말 것. 깃 커밋에서 되찾는 쪽이 빠름
  - 재현 테스트 횟수의 정확한 수치
---

## 맥락
## 나의 기여
## 트러블슈팅 과정
## 선택과 기각한 대안
## 결과
## 배운 점
```

**여섯 칸 모두 채우거나 `open_questions`에 남긴다.** 뒤의 넷이 기술면접 꼬리질문이 파고드는 자리다.

`나의 기여`는 팀이 한 일과 분리해서 적는다. "팀이 개선했습니다"는 면접에서 감점되는 형태다.

### 모르는 값

**비워 두는 것이 지어내는 것보다 항상 낫다.** 모르는 필드는 `~`로 두고 `open_questions`에 한 줄 남긴다.

3회 미도달로 park한 칸은 **어느 각도를 이미 썼는지와 되찾을 경로**를 함께 적는다. 그게 없으면 다음 세션이 같은 자리를 다시 파고, 사용자는 같은 질문을 네 번째로 받는다.

`date:`는 사용자가 확신하는 해상도까지만 적는다 — `2025-04`, `2025-봄`, `2025` 모두 유효하다. 월을 확신하지 못하는데 월을 적으면 그건 지어낸 것이다.

### evidence

| 값 | 뜻 | 판정 |
|---|---|---|
| `verified` | 제3자가 확인 가능한 흔적이 있다 — 커밋·PR·문서·같이 일한 사람·근무기록·수상 | **흔적을 실제로 열어 확인했을 때만.** "있을 것 같다"는 `recalled` |
| `recalled` | 본인 기억에 근거한다. **정상 상태다.** 소프트 스킬 경험은 대부분 여기다 | 기본값 |
| `unacquired` | 아직 일어나지 않았다. 획득 계획으로 관리하고, 자소서·면접에서는 인용하지 않는다 | 사용자가 "그건 아직 안 해봤다"고 말했을 때 |

저장소 스캔(`scripts/repo_scan.py`)은 승급 근거가 아니다. 그날 커밋이 있다는 것만 확인했지 그 장면의 흔적을 연 것이 아니다. `recalled`로 남는다.

## 여러 사건이 이어진 경우

"세 번 실수하고 네 번째에 고쳤다"는 하나가 아니라 넷이다 — 사건 셋과 종합 하나. 각각을 에피소드로 두고 종합 쪽에서 `related:`로 가리킨다. 하나로 합치면 각 사건의 트러블슈팅이 사라지고, 면접에서 "그 셋이 각각 왜 일어났죠?"에 답할 것이 없어진다.

## 프로젝트

```markdown
---
id: secondhand-market
title: 중고거래 플랫폼
period: 2025-03 ~ 2025-04 (6주)
team: 6명 (백엔드 3)
role: 백엔드
stack: [Java 17, Spring Boot 3, MySQL, Redis, Docker]
links:
  repo: ~
---

<!-- 아래 세 섹션은 직접 쓰는 자리입니다. 에피소드 인터뷰에서는 나오지 않는 내용이라 비워 둡니다. -->

## 배경 / 목적

## 내가 맡은 범위

## 성과
```

**frontmatter만 채우고 산문 세 섹션은 비워 둔다.** 이건 한 에피소드에서 나오는 정보가 아니라서, 채우려면 대신 써주는 수밖에 없다. 그 대신 에피소드의 `open_questions`에 "프로젝트 배경·성과 미작성"을 올려 사용자가 나중에 직접 쓰게 남긴다.

frontmatter 정보는 인출 틀 없이 그냥 묻는다. 기억 인출이 아니라 사실 조회다. 모르는 값은 `~`.

기간·인원·스택은 여기 한 번만 적고 에피소드는 참조로 물려받는다. 서류 심사에서 인사담당자가 5~10초 안에 보는 것이 이 목록이다.

## self.md

```markdown
# 역량 주장

## 협업을 잘하는 편이다
- 상태: 후보
- 근거: []
- 반례: []
- 나온 곳: 2026-08-17, concurrent-payment-lock 채굴 중
```

- **`상태: 후보`** — 근거 에피소드가 0개인 상태. 사용자가 인터뷰 중에 뱉은 자기 서술을 그대로 받아 둔 자리다. 원칙을 어기는 게 아니라, **어기려는 시도를 눈에 보이게 잡아 두는 자리**다. 자소서·면접에서 인용하지 않는다.
- **`상태: 근거있음`** — `근거`에 에피소드 id가 하나 이상 붙었을 때. 여기부터 인용 가능하다.
- **`반례`** — 이 주장과 어긋나는 에피소드. 예: "꼼꼼하다"는 주장에 "환경변수 누락으로 배포 실패" 사건. 반례가 붙은 주장을 그대로 자소서에 쓰면 면접에서 무너진다.

제목은 **사용자 표현 그대로** 쓴다. "협업 역량 보유"로 다듬지 않는다.

같은 사람이 여러 주장을 갖는 것이 정상이다 — 같은 에피소드들이 금융권에서는 `꼼꼼하고 정확한`으로, 스타트업에서는 `빠른 실행`으로 묶인다. 하나로 수렴시키지 않는다.

## backlog.md

```markdown
# 다음에 캘 것

- 병원예약 때 로그인이 자꾸 풀리던 것 — 2026-08-17 세션에서 언급, 안 캠
- (2단계에서 고르지 않은 후보도 여기에)
- AI검증 축 — 2026-08-17에 열었으나 "AI 코드는 그냥 읽고 쓰지 따로 고친 기억이 없다", 장면 없음
```

인터뷰 중에 사용자가 꺼냈지만 그 세션에서 캐지 못한 장면. 여기 적지 않으면 세션이 끝날 때 증발한다.

**여는 질문을 던졌는데 장면이 없던 축도 같은 목록에 적는다.** 거절은 에피소드를 만들지 않으므로 `index.md` 커버리지에서 **아직 안 물어본 0과 구분되지 않는다.** 여기 적지 않으면 다음 세션의 앵커 선택이 같은 축을 다시 연다. 절을 따로 두지 않는다.

## index.md

`scripts/build_index.py`가 만든다. 형식은 그 스크립트가 정의하고, 저장소가 비어 있어도 만든다.

**파생 캐시다.** 진실은 언제나 개별 파일의 frontmatter이고, 사용자가 그 파일을 직접 고치는 것이 정상 동작이다. 그래서 index를 읽기 전에 매번 다시 만든다.

담는 것: 프로젝트 목록 · 에피소드 목록(프로젝트·역량·증거·미해결 수) · 이어지는 사건의 선행/후속 · 역량 커버리지.

`related:`는 한 방향으로만 저장하고 `후속` 열은 index가 역으로 계산한다. **역량 커버리지는 어휘 전체를 0 포함해 나열한다** — 0인 축이 다음에 캘 자리를 가리키는 것이 그 줄의 용도다.
