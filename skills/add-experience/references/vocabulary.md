# 앵커와 어휘

역량 태그와 여는 질문은 **같은 표에서 나온다.** 따로 관리하면 태그는 있는데 캘 질문이 없거나, 캤는데 붙일 태그가 없는 축이 생긴다.

## 역량

`skills:` 태그이면서 동시에 앵커다. 여는 질문은 **장면의 종류만 지목하고 답의 방향은 비워둔다.**

| 태그 | 여는 질문 |
| --- | --- |
| 디버깅 | "원인을 못 찾아서 오래 붙잡고 있었던 에러가 있었나요?" |
| 기술선택설명 | "두 가지 방법 중에 골라야 했던 적이 있었나요?" |
| 갈등 | "팀에서 의견이 갈렸던 적이 있었나요?" |
| 요구사항해석 | "무엇을 만들어야 하는지가 애매했던 적이 있었나요?" |
| 복잡도감각 | "느려서 방식을 바꾼 적이 있었나요?" |
| AI검증 | "AI가 짜준 코드를 그대로 못 쓰고 고친 적 있나요?" |
| 협업·설명 | "개발하지 않는 사람에게 기술적인 걸 설명해야 했던 적이 있었나요?" |
| 프로세스개선 | "같은 문제가 반복돼서 방식을 바꾼 적이 있었나요?" |
| 실패 | "돌이켜보면 후회되는 결정이 있었나요?" |
| 리더십 | "아무도 안 하고 있던 일을 본인이 떠맡은 적 있나요?" |
| 커뮤니케이션 | "설명이 잘 안 통해서 다시 설명한 적 있나요?" |
| 주도성 | "시키지 않았는데 먼저 한 게 있나요?" |

앞 여섯은 2026년 기준 기업이 개발자에게 요구한다고 서술하는 역량 축이다. 나머지는 자소서 상황 문항과 임원 면접이 파고드는 자리다.

## 어느 앵커부터 여는가

`index.md` 역량 커버리지의 **`역량:` 줄에서 0인 축부터** 고른다. `주제:` 줄은 여는 질문이 없으므로 여기서 고르지 않는다. 저장소가 비어 있으면 표의 위에서부터 간다 — `디버깅` → `기술선택설명` → `갈등` 순이다. 앞의 둘은 신입에게도 장면이 남아 있을 확률이 높고, 셋째는 자소서 문항이 가장 많이 요구하는 자리다.

**한 번에 하나만 던진다.** 열두 개를 나열하면 "다 아닌 것 같은데요"가 돌아온다.

## 어휘를 늘릴 때

표에 없는 개념이 필요하면 사용자에게 확인하고 이 파일의 표에 행을 추가한 다음 쓴다. 역량을 추가할 때는 여는 질문도 같이 쓴다. 표를 고치는 것이 어휘를 늘리는 유일한 경로다.

`scripts/build_index.py`가 이 파일의 표 첫 열을 읽어 커버리지를 만든다.
