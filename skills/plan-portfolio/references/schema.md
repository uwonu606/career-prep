# 저장 형식 — 만들 것

`add-company` 의 `references/schema.md` 와 **같은 저장소(`career/`)에 공존**한다. slug·`~`·`open_questions`·"비워 두는 것이 지어내는 것보다 항상 낫다"는 그 규약을 그대로 잇는다.

## 레이아웃

```
career/
├── companies/<slug>/{company.md, artifacts/}     add-company 가 만든다 — 회사만 담는다
├── episodes/·projects/                            add-experience 가 만든다 — 나만 담는다
└── applications/<slug>/
    ├── portfolio.md
    └── artifacts/     이 스킬이 새로 판 자료 — 원문 그대로. 편집하지 않는다
```

**`applications/` 는 회사×나의 자리다.** `companies/` 는 회사만, `episodes/`·`projects/` 는 나만 담고, 둘을 대조한 것이 여기 온다. `projects/<slug>/{project.md, artifacts/}` 와 같은 모양이다 — `artifacts/` 는 원자료의 자리라 손대지 않고, 해석은 `portfolio.md` 에만 쓴다.

## slug

**`career/companies/<slug>/` 의 slug 를 그대로 쓴다.** 새로 짓지 않는다 — 같은 회사가 두 이름으로 갈리면 다음 실행이 어느 쪽을 볼지 모른다. 같은 회사에 두 직무로 지원해 만들 것이 둘이면 `portfolio.md` 하나 안에 후보로 함께 두고, 고른 것 하나만 `picked` 에 온다.

## portfolio.md

아래는 형식을 보이기 위한 예시다 — `<…>` 는 전부 자리표시이고 어느 값도 조사값이 아니다.

```markdown
---
id: <회사 slug>                  # companies/<slug> 와 같은 값. 그것이 곧 참조다
company: <법인명>
date: 2026-09-07                 # 이 파일을 마지막으로 고친 날
company_date: 2026-09-06         # 근거로 쓴 company.md 의 조사일
job_url: ~                       # company.md 에서 가져온다. 없으면 ~
status: 재현                     # 후보 · 재현 · 확정 · 만듦
picked: <만들 것 한 줄>           # 3단계 전에는 ~
episodes: [<에피소드 id>]         # 이 기획이 잇는 기존 기록. 없으면 []
open_questions:
  - 후보 3 재현 실패(각도 10) — 공개 엔드포인트가 인증을 요구해 밖에서 못 부름
---

## 문제 지도

| 번호 | 각도 | 상태 | 후보 또는 사유 |
|---|---|---|---|
| 1 | 반복되는 요건 | 있음 | 후보 1 |
| 2 | 새로 여는 직군 | 없음 | 공고 <N>건의 직군이 이전 조사와 같음 |
| 3 | 공고가 쓴 문제 서술 | 있음 | 후보 2 |
| … | | | |
| 8 | 제품 직접 사용 | 수동 | 사용자가 아직 안 재 봄 — 3단계에서 다시 청함 |
| 15 | 탐색: <자리 이름> | 없음 | company.md 19행에 문제 서술 없음 |

## 후보

- **1. <문제 한 문장>** — 자백 · 공고 <N>건 중 <M>건이 <요건>을 반복 [출처](https://<공고 목록 URL>)
  잇는다 — `episodes/<id>` 에 같은 종류의 작업이 있다
- **2. <문제 한 문장>** — 자백 · *"<공고 본문 인용 한 줄>"* [출처](https://<공고 URL>)
  획득 — `backlog.md` 의 획득 줄과 같은 자리다
- **3. <문제 한 문장>** — 추측 · <숫자 출처> × <글 출처> 를 내가 이었다
  비운다 — <내부 데이터가 있어야 하는 이유>

## 재현

**기준**(값을 보기 전에 적음). <무엇이 나오면 재현인가 한 줄>

**결과.** <잰 값 한 문장> [관측 2026-09-07 <앱 v3.2.1 / iPhone 14 / 홈 진입 3회 평균>]

<기준에 닿았는지 한 줄과, 닿지 않은 후보를 왜 뺐는지> [관측 2026-09-07 <무엇을 어떻게>]

## 만들 것

**무엇.** <한 문장>

**겨눈 자백.** 후보 <N> — *"<인용 한 줄>"* [출처](https://<URL>)

**재현으로 확인된 것.** <값 한 문장> [관측 2026-09-07 <무엇을 어떻게>]

**내 재료와의 연결.** <잇는다면 에피소드 id 와 어느 칸이 닿는지 / 획득이면 무엇이 새로 생기는지>

**범위.**
- 바닥 — <여기까지 되면 내놓는다>
- 천장 — <여기부터는 안 한다>

**어떻게 보이나.** <결과물의 형태 — 리포지토리·데모·측정 리포·PR 중 무엇이고 어디에 두나>

**받을 질문.**
- **왜 이걸 골랐나** — <답>
- **회사 내부 사정을 모르면서** — <답>
- **만든 것의 한계** — <답>

## open_questions

- **후보 3 재현 실패(각도 10)** — 공개 엔드포인트가 인증을 요구해 밖에서 못 불렀다. 되찾기: 회사가 샌드박스 키를 공개하면 다시. 같은 후보를 다음 실행에서 다시 파지 말 것.
```

**frontmatter 에 숫자 모양 필드를 두지 않는다** — 잰 값·기간·난이도 점수 칸을 만들면 모르는 값을 채우게 된다(`add-company/references/schema.md` 와 같은 이유, rationale #13·#19). 숫자는 본문에 출처와 함께만 온다.

`open_questions` 는 frontmatter 한 줄 + 본문 상세이고 **두 목록의 항목 수는 같다.**

## status — 갱신 모드가 어디로 들어가나

| status | 뜻 | 다시 실행하면 |
|---|---|---|
| `후보` | 지도와 후보가 있고 아직 안 골랐다 | 2단계 |
| `재현` | 골랐고 되살리는 중이다 | 3단계 |
| `확정` | 만들 것이 정해졌고 아직 안 만들었다 | 4단계에서 다듬거나, 방향을 바꾸겠다면 2단계 |
| `만듦` | 만들었고 에피소드가 생겼다 | `episodes:` 에 id 를 잇고 남은 `open_questions` 를 읽어준다 |

사용자가 방향을 바꾸겠다고 하면 `status` 와 무관하게 2단계로 되돌린다. 이전 후보와 재현은 지우지 않고 그대로 둔다 — 뺀 이유가 다음 실행의 자산이다.

## 본문 5섹션 — 고정

순서와 제목을 바꾸지 않는다. 다른 섹션을 추가하지 않는다.

### 문제 지도

14행 + 탐색 행. 순서는 `catalog.md`. 열은 `번호 | 각도 | 상태 | 후보 또는 사유`.

| 상태 | 뜻 | 후보/사유 칸 |
|---|---|---|
| `있음` | 그 각도에서 후보가 나왔다 | 후보 번호(본문 후보 절과 이어진다) |
| `없음` | 자료를 끝까지 읽었는데 문제가 안 적혀 있다 | **무엇을 어디까지** 읽었는지 |
| `수동` | 사용자가 해 봐야 하는 각도인데 아직 안 했다 | 무엇을 청했는지 |
| `실패` | 자료 자체에 못 닿았다 | 사유 + `open_questions` 참조 |

**"없음"도 정보다.** 기술블로그가 글 끝에 남은 과제를 안 쓰는 회사, 공고에 문제 서술이 없는 회사는 그 사실이 회사를 말한다. 빈 행은 없다.

`company.md` 지도에서 이미 `없음`·`실패` 인 각도는 여기서도 그대로 `없음`·`실패` 이고, 사유 칸에 `company.md 지도 <N>행` 을 적는다 — 같은 자리를 두 번 파지 않는다.

### 후보

**등급이 먼저, 출처가 끝에.** 형태는 라벨 목록이다 — 항목마다 등급·출처·내 재료 연결이 달라 칸이 안 맞는다.

    - **<번호>. <문제 한 문장>** — <등급> · <근거 한 문장> [출처]
      <잇는다 | 획득 | 비운다> — <한 문장>

**인용은 그대로 옮긴다.** 회사 문장을 요약하면 내 문장이 되고 등급이 자백에서 추측으로 내려간다. 인용 한 줄 + 출처가 자백의 최소 단위다.

숫자는 원자료 값을 그대로 옮기고, 계산한 값은 두 원값과 함께 쓴다 — "정규직 1,200 → 1,656(+38%)".

**후보를 뺄 때 지우지 않는다.** 재현 실패·사용자 제외로 빠진 후보는 목록에 남기고 끝에 *"— 뺌: <사유>"* 를 붙인다. 지우면 다음 실행이 같은 자리를 다시 판다.

### 재현

**기준이 결과보다 먼저 온다.** 순서를 바꾸면 값을 보고 기준을 맞춘 것과 구별되지 않는다.

관측의 출처 표기는 `[관측 YYYY-MM-DD <무엇을 어떻게 쟀나>]` 다. URL 이 없는 자리라 **무엇을·언제·어떤 조건에서** 가 출처를 대신한다. 앱이면 버전과 기기, 호출이면 엔드포인트와 시각, 예제면 코드가 있는 경로까지 적는다.

### 만들 것

칸 순서를 바꾸지 않는다 — 무엇 → 겨눈 자백 → 재현으로 확인된 것 → 내 재료와의 연결 → 범위 → 어떻게 보이나 → 받을 질문. **근거가 결론 뒤에 온다**: 무엇을 만드는지 먼저 읽히고, 왜 그것인지가 따라온다.

받을 질문 셋은 `catalog.md` #7 의 세 각도 그대로이고 순서도 그대로다. 답이 없는 칸은 `~` 로 두고 `open_questions` 에 올린다 — 빈칸이 곧 면접에서 막히는 자리다.

### open_questions

못 채운 것 + **어느 각도였고 어디서 되찾나.** 지도의 `실패` 행과 뺀 후보는 여기에도 반드시 있다. 되찾을 경로(다시 부를 명령, 사용자가 해 볼 것, 회사 쪽에서 무엇이 바뀌면 다시 볼 수 있는지)를 든다.

이게 없으면 다음 실행이 같은 후보를 다시 파고, 같은 재현을 네 번째로 시도한다.

## 하지 않는 것

- **핏·합격 가능성.** "이 회사와 맞다/안 맞다", "이 정도면 된다"를 쓰지 않는다(불변 원칙 1). 격차는 없는 항목의 나열이고, 고르는 것은 사용자다
- **출처 없는 문제 문장.** 등급이 안 붙으면 후보가 아니다
- **`artifacts/` 편집.** 새로 판 자료는 원문 그대로 둔다. 정리하고 싶으면 `portfolio.md` 에 출처를 달아 쓴다
- **각도별 섹션.** 각도는 지도의 행과 후보의 출처로만 등장한다
- **"귀사의 문제를 풀었습니다" 라는 틀.** 만든 것은 *"공개된 자리를 밖에서 재현해 이렇게 접근했다"* 로 적는다 — 밖에서 본 것은 밖에서 본 것이다

## 갱신

같은 회사를 다시 실행하면 **새 파일이 아니라 같은 `portfolio.md` 를 갱신**하고 `date` 와 `status` 를 바꾼다. `company.md` 의 `date` 가 바뀌었으면 `company_date` 도 갱신하고, 지도에서 달라진 행은 *"2026-03 없음 → 2026-09 있음"* 꼴로 표시한다 — 달라진 것 자체가 회사의 변화다.

`artifacts/` 는 덧붙이고 지우지 않는다. 이름이 겹치는 산출은 이전 것을 `<이름>-<이전 date>.<확장자>` 로 옮긴 뒤 새로 쓴다.
