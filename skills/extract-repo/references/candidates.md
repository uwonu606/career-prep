# 재료

재료 한 건은 리포에 남은 **흔적**이다. 어디서 찾았는가가 축이고, 하나의 문제를 두고 이어진 커밋·PR·이슈가 사건 하나이고, 사건 하나가 칸 일곱으로 적힌다. 어느 문서에 맞는지·얼마나 강한지는 고르는 쪽의 일이라 칸이 없다.

## 1. 축 일곱

훑는 순서이자 `candidates.md`의 절 순서다. 축마다 "어디에 남나"를 **전부** 댄다.

| 축 | 어디에 남나 | 무엇이 재료인가 |
|---|---|---|
| 도메인·문제 | README, `docs/`, 이슈 본문, 도메인 모델 코드(엔티티·용어), 마이그레이션 | 누구의 어떤 문제를 풀었나, 도메인 규칙을 코드로 옮긴 자리, 요구가 바뀐 흔적 |
| 구조·기술 선택과 대안 | ADR·설계 문서, 매니페스트의 의존성 추가·교체, 되돌린 커밋, 큰 리팩토링 PR, 설정 파일 | 왜 이 구조·라이브러리인가, 버린 대안, 교체의 이유 |
| 장애·버그와 수정 | 수정 커밋과 **뒤따른 테스트 커밋**, 이슈의 재현 단계, hotfix 태그, 롤백 | 무엇이 어떻게 깨졌고 어떻게 찾아 고쳤나, 재발 방지 |
| 성과·수치 | 커밋·PR 본문의 숫자, 벤치마크·프로파일 파일, 릴리스 노트 | 응답 시간·비용·코드량·커버리지의 전후 |
| 과정·협업 | PR 설명의 구조, 리뷰 대화(요청·반영·거절), 이슈 응답, 커밋 메시지 규약, 템플릿 | 설명하는 방식, 피드백을 받고 주는 방식, 규약을 만든 흔적 |
| 에이전트 활용과 검증 | `CLAUDE.md`·`AGENTS.md`·`.claude/`·`.cursor/`·`.mcp.json`·스킬 디렉토리, `Co-Authored-By` 트레일러가 붙은 커밋 **직후의** 수정·테스트 커밋, `evals/`, 훅 스크립트 | 에이전트에게 준 맥락과 규칙, 산출물을 어떻게 검증했나, 에이전트용 도구를 만든 흔적 |
| 그 밖 | 위에 안 드는 것 전부 | 스크립트·자동화, 문서화, 접근성·국제화, 라이선스 정리 같은 것 |

에이전트 활용 축의 재료는 **검증**이다. 트레일러가 붙은 커밋은 그 뒤에 온 테스트·수정·되돌림을 찾으라는 표지다.

## 2. 사건

재료 한 건은 커밋이 아니라 **사건**이다 — 하나의 문제를 두고 이어진 커밋·PR·이슈의 묶음. 묶는 근거는 우선순위대로 같은 PR → 같은 이슈 번호(본문·브랜치명·`#n`) → 같은 파일을 짧은 간격으로 건드린 커밋이다. "세 번 배포 사고 뒤 체크리스트"처럼 사건이 여럿 이어지면 각각을 한 건으로 두고 `이어짐:`으로 잇는다.

## 3. 칸 일곱

| 칸 | 뜻 |
|---|---|
| `C<n>. 요지` | 사건을 한 줄로. 무엇을 왜 어떻게 |
| 축 | 절이 곧 축이다. 두 축에 걸칠 때만 칸을 적고, 절은 첫 축에 둔다 |
| 이유 | 왜 소재가 될 수 있나 한 줄 — 판정이 아니라 설명이다 |
| 근거 | 커밋 sha(짧게)·PR/이슈 번호·`경로:줄`. 하나 이상 |
| 종류 | **직접** — 그 사실이 그대로 적혀 있다(PR 본문의 수치, 테스트 파일, ADR 문장). **정황** — 사실 여럿을 이어 읽었다(커밋 간격으로 본 검증 습관, 의존성 교체로 본 선택) |
| 확인 필요 | 리포로 못 밝힌 것 한 줄. 없으면 `~`. 실제 트래픽·매출, 팀 규모와 역할, 1인 리포의 협업, 본인 관여 정도가 여기 온다 |
| 이어짐 | 이전 실행이나 앞 번호의 사건과 이어질 때 `C<n>` |

## 4. 누구의 것을 뽑나

본인이 **저자·리뷰어·이슈 작성자**인 사건이 재료다. 본인 여부는 `commits.json`의 `mine`(저자 이메일이 `identities`에 있음)과 PR·이슈의 `author`가 `gh_login`과 같음이다. `identities`가 비어 있으면 전부를 뽑되 건마다 `저자:`를 붙이고 `확인 필요: 본인 식별 안 됨`을 적는다.

타인의 사건은 두 경우에 `함께 한 것` 절로 간다 — 내 사건과 이어졌거나(같은 PR·같은 모듈·내가 리뷰), 프로젝트의 대표 기능이거나. 저자 이름을 제목에 붙이고 `확인 필요`에 본인 관여 정도를 적는다. 그 밖의 타인 작업은 `repo.md`의 규모 표에만 반영된다.

## 5. 파일 모양

`career/repos/<slug>/candidates.md`. 축 절 일곱 + `함께 한 것` 절이 항상 있고, 재료가 없는 절은 `없음 — <무엇을 봤는지>` 한 줄이다. 원자료는 `artifacts/`(`git/summary.json`·`git/commits.json`·`gh/prs.json`·`gh/issues.json`·`gh/reviews/<n>.json`)에 있다.

```markdown
---
id: <slug>
count: 37                        # 마지막 C<n>
runs:
  - {at: 2026-09-09, from: ~, to: <sha>, added: 37}
  - {at: 2026-10-02, from: <sha>, to: <sha>, added: 5}
---

# <리포 이름> 재료

- 종류: 직접
- 확인 필요: ~

## 구조·기술 선택과 대안

- 확인 필요: <리포로 못 밝힌 것 한 줄>
```
